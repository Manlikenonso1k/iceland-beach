Implementation Guide
Step 1: Initiate Payment Transaction
Make a POST request to initiate the payment transaction from your backend:

Do not initiate payments from the frontend
Do not call POST /integration/api/v1/payment/initiate directly from browser or mobile client code.

For payment integrations, the global security standard is to create payment sessions server-to-server so the merchant backend remains the trusted source of truth for amount validation, transaction-reference generation, order integrity checks, fraud screening, logging, and audit controls. Calling this endpoint from the frontend weakens those controls and increases the risk of manipulated requests and unauthorized transaction creation.

Endpoint:

POST https://integration-servl.tgipay.com/integration/api/v1/payment/initiate

Headers:

{
  "Content-Type": "application/json",
  "integration-key": "YOUR_PUBLIC_KEY"
}

Callback Handling
After payment completion, TGIPAY will redirect the customer back to your configured callback URL with the payment status. The tgipay query parameter is a numeric indicator and is always 1.

// Example callback URL: https://your-site.com/payment-callback?status=success&ref=123&tgipay=1
app.get('/payment-callback', (req, res) => {
  const { status, ref, tgipay } = req.query;
  
  if (status === 'success') {
    // Handle successful payment
    console.log(`Payment successful for transaction: ${transactionReference}`);
    res.redirect('/payment-success');
  } else {
    // Handle failed payment
    console.log(`Payment failed for transaction: ${transactionReference}`);
    res.redirect('/payment-failed');
  }
});

Payment Flow States
The Direct Integration UI Redirect follows these payment states:

graph TD
    A[Payment Initiated] --> B[Customer Redirected]
    B --> C[Payment Form Loaded]
    C --> D{Customer Action}
    D -->|Enters Details| E[Processing Payment]
    D -->|Cancels| F[Payment Cancelled]
    E --> G{Payment Result}
    G -->|Success| H[Payment Completed]
    G -->|Failed| I[Payment Failed]
    H --> J[Redirect to Success URL]
    I --> K[Redirect to Failure URL]
    F --> L[Redirect to Cancel URL]

State Descriptions
State	Description	Next Actions
Initiated	Payment request created, awaiting customer action	Redirect customer to payment URL
Processing	Customer is entering payment details	Monitor for completion
Completed	Payment successful, funds captured	Update order status, send confirmation
Failed	Payment attempt unsuccessful	Offer retry options, log for analysis
Cancelled	Customer cancelled the payment	Return to merchant site, log abandonment
